## Часть B. Оконные (накопительные) функции

### Проблема, которую они решают

`GROUP BY` **схлопывает** строки: было 5 экзаменов студента, осталась 1 строка со средним.
А что если нужны **и** все 5 строк, **и** рядом с каждой какой-то итог? Например:

```
дата        оценка   сумма кредитов «на сегодня»
2026-01-15    5        6
2026-01-20    4       13   ← 6 + 7
2026-01-25    5       18   ← 6 + 7 + 5
```

Это **накопительный итог** (running total). С `GROUP BY` его не сделать, а оконной функцией легко.

### Оконная функция = агрегат + `OVER (...)`

```sql
SUM(credits) OVER (PARTITION BY student_id ORDER BY exam_date)
```

Читается так: «для **текущей** строки посчитай SUM по **окну** строк вокруг неё».
**Строки не схлопываются**: сколько было на входе, столько и на выходе, просто добавляется столбец.

В скобках `OVER` три настройки:

| Что пишем | Что значит | Аналогия |
|---|---|---|
| `OVER ()` | окно = вся таблица | «общий итог в каждой строке» |
| `PARTITION BY x` | окно = только строки с таким же `x` | как GROUP BY, но **без схлопывания** |
| `ORDER BY y` | окно = от первой строки **до текущей** | это и есть **накопление** |

### Пример на пальцах

Таблица попыток Иванова:

```
course   date   grade
АиСД     15.01   5
Матан    20.01   4
ДА       25.01   5
```

```sql
SELECT course, grade,
       AVG(grade) OVER ()                    AS avg_all,      -- среднее по всем строкам
       SUM(grade) OVER (ORDER BY date)       AS running_sum,  -- накопительная сумма
       AVG(grade) OVER (ORDER BY date)       AS running_avg   -- средний «на этот момент»
FROM ...
```

```
course grade avg_all running_sum running_avg
АиСД     5    4.67       5          5.00        окно: [АиСД]
Матан    4    4.67       9          4.50        окно: [АиСД, Матан]
ДА       5    4.67      14          4.67        окно: [АиСД, Матан, ДА]
```

Видно, что `ORDER BY` внутри `OVER` с каждой строкой **расширяет окно на одну строку**. Отсюда и
название «накопительная»: каждая следующая строка видит всё, что было до неё.

Добавим `PARTITION BY student_id`, и накопление будет **начинаться заново** для каждого студента.

### Подвох: одинаковые значения в ORDER BY

По умолчанию `ORDER BY` в окне означает «все строки до текущей **и все равные ей**»
(`RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`). Если у двух строк одна дата, они получат
**одинаковую** накопленную сумму, сразу за обе. Чтобы считать строго по одной строке:

```sql
SUM(credits) OVER (PARTITION BY student_id
                   ORDER BY exam_date, course_name          -- добавили «разрыв ничьей»
                   ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
```

`ROWS BETWEEN 2 PRECEDING AND CURRENT ROW` даёт «скользящее» окно из 3 строк
(скользящее среднее за 3 последние попытки).

### Функции, которые бывают только оконными

| Функция | Что даёт | Для оценок 5, 5, 4, 3 |
|---|---|---|
| `ROW_NUMBER()` | номер строки, без повторов | 1, 2, 3, 4 |
| `RANK()` | место с пропусками после ничьей | 1, 1, 3, 4 |
| `DENSE_RANK()` | место без пропусков | 1, 1, 2, 3 |
| `LAG(x)` | значение `x` из **предыдущей** строки окна | NULL, 5, 5, 4 |
| `LEAD(x)` | значение `x` из **следующей** строки окна | 5, 4, 3, NULL |

Для них в `OVER` обязателен `ORDER BY`, иначе непонятно, какая строка «предыдущая».

### Где их можно писать и где нельзя

Оконные функции считаются **после** `WHERE`, `GROUP BY` и `HAVING`, но **до** `ORDER BY`:

```
FROM/JOIN → WHERE → GROUP BY → HAVING → [ОКНА] → SELECT → ORDER BY
```

Из этого порядка получаются три правила:

1. **В WHERE и HAVING оконную функцию писать нельзя**: она ещё не посчитана.
   Решение: посчитать её в CTE и фильтровать во внешнем запросе.
   ```sql
   WITH r AS (SELECT ..., DENSE_RANK() OVER (...) AS place FROM ...)
   SELECT * FROM r WHERE place <= 3;
   ```
2. **Окно можно навесить на агрегат**, потому что GROUP BY уже прошёл:
   ```sql
   SELECT month, COUNT(*)                       AS exams,
          SUM(COUNT(*)) OVER (ORDER BY month)   AS exams_running   -- накопительно по месяцам
   FROM ... GROUP BY month;
   ```
   Внутренний `COUNT(*)` обычный (по группе), внешний `SUM(...) OVER` оконный (по уже готовым строкам-группам).
3. Окна в одном SELECT могут быть разными: в одном столбце `PARTITION BY group`, в другом `OVER ()`.

### GROUP BY или окно?

| Нужно | Чем делать |
|---|---|
| одна строка на группу | `GROUP BY` |
| каждая строка + итог её группы рядом | `AVG(x) OVER (PARTITION BY группа)` |
| накопленная сумма, «на сегодняшний день» | `SUM(x) OVER (ORDER BY дата)` |
| место / рейтинг / топ-N в каждой группе | `RANK` / `DENSE_RANK` + CTE + `WHERE place <= N` |
| сравнение с предыдущей строкой | `LAG` |
